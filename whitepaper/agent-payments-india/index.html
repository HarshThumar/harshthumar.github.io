Agent Authorization for Indian Payments, Formally

What a UPI-Style Mandate Must Cryptographically Bind When an AI Agent Pays, and Which Defensive Checks Protect What.

Harsh Thumar · Remote Participant, IETF · Independent Researcher · 15 November 2026
Public Research Notice

1. Executive Summary

As artificial intelligence agents transition from informational assistants to transactional actors, they are increasingly tasked with executing financial operations on behalf of human principals. In India, the Unified Payments Interface (UPI) ecosystem has established a global benchmark for instant retail payments. Through NPCI's UPI Circle initiative (introduced in circular OC 201 and expanded to IoT devices and software entities in addendum OC 201-B), India already possesses a production framework for delegating payment authority from a primary account holder to a secondary user or automated software agent.

The central engineering and cryptographic question is:

When an autonomous software agent executes payments under a delegated mandate, what guarantees that every debit remains strictly within the bounds approved by the human principal?

To answer this question without relying on informal assertions, we developed a machine-checked formal protocol model in the Tamarin prover (models/05_agent_payment_mandate.spthy). The model formalizes the interaction between a human principal (payer), an authorization server (issuing PSP/bank), an autonomous software agent, a payment server (acquiring PSP/switch), and an active Dolev-Yao network attacker.

Security Property Necessary and Sufficient Check Set in Formal Model
P10 (Debit within intent) Principal consent binding + Payee exact match + Amount cap + Payment server audience check
P11 (No debit after cancellation) Per-payment real-time online revocation lookup at the payment server
P12 (Authentic agent requests) Cryptographic proof-of-possession (DPoP sender-constraint)

2. What an Agent Payment Mandate Must Bind

To resist symbolic and real-world adversaries, a payment mandate must serve as a cryptographically verifiable capability token binding six non-negotiable parameters:

  1. Payer Approval (Consent Stamping): Evidence that the primary account holder authorized the specific parameters over an authenticated channel.
  2. Payee Restriction: Explicit Virtual Payment Address (VPA) or merchant identifier (exact string match).
  3. Transaction & Cumulative Amount Caps: Strict financial limits defining single-transaction thresholds and cumulative period ceilings.
  4. Audience Restriction (RFC 8707): Identification of the single designated payment server / switch authorized to process debits under it.
  5. Agent Key Binding (Proof of Possession / RFC 9449 DPoP): Stamped public key of the agent, requiring fresh cryptographic signatures per payment.
  6. Online Revocation Endpoint (RFC 7009): Real-time lookup verifying mandate validity at the moment of debit execution.

3. Alignment with Indian Frameworks

We mapped the machine-checked findings to Indian regulatory, policy, and technical frameworks:

Regulatory & Technical Alignment
  • NPCI UPI Circle (OC 201 & OC 201-B): Formally proves the security boundaries required for Mode 1 (Full Delegation: Spend With Limit) for software delegates.
  • RBI FREE-AI Committee Report: Supports the core Sutras of Trust, Accountability, Resilience, and Explainability through deterministic cryptographic verification.
  • DPDP Act 2023: Guarantees specific consent via rich authorization parameters and withdrawable consent via synchronous online revocation.

4. Implementation Checklist

PSPs, banks, and payment network operators should verify:

  1. Capture primary human consent out-of-band via biometric or MPIN authentication.
  2. Stamp exact payee VPA, caps, payment server audience, and agent public key into signed mandate JWTs.
  3. Enforce strict DPoP proof-of-possession verification for every outbound debit request.
  4. Query synchronous online revocation registries before committing debits.
